# Release 2026-11-23 — saves on the server fixed; SAP capital lines and the reconciliation report (ADR-0036)

Date: 23/11/2026
Operator: Marios on the server (`ecapital-release-on-server --ref claude/ecstatic-cray-g0zhkx`)
Migrations: 0026 `sap_capital_lines`, applied by the release script. Seed: none.

## What this release brings

- **Fix: every save on the server was refused with 403** («Request to
  /projects failed with 403», owner report 23/11/2026). Behind cloudflared
  and nginx the app saw its own address as `http://…` while the browser sent
  `https://…`, and its safety check refused every create, edit and upload.
  The check now also accepts the public address set in `web.env`
  (`NEXT_PUBLIC_APP_ORIGIN`, confirmed `https://ecapital.shso.online` on
  23/11). A request from another site is still refused.
- **SAP capital spending lines** (ADR-0036): a new import on «Εισαγωγή από
  SAP» from the file SAP administration's connector produces, or straight
  from the connector once its key is on the server. Lines match by `CAP-`
  reference, then by the eFinance invoice (vendor number, amount, date), then
  by remembered rules, then the queue. On a contract eFinance already knows
  they never add to the spent figure.
- **ME2N and KSB1 are retired**: SAP has no WBS and its purchase orders are
  stock only. Old batches stay. FBL1N stays.
- **New report «Συμφωνία SAP με eFinance»**: per contract, what SAP posted on
  the capital accounts against what eFinance booked, the difference and a
  status, with Excel.

check and stopped only because the test carries no sign-in; before this
release it was `403`.

The connector settings `SAP_CONNECTOR_URL` and `SAP_CONNECTOR_KEY` are not
set in this release. «Λήψη από το SAP» says the connection is not set up,
and the file upload works. The key goes in later, file to file, never by
e-mail or chat.
