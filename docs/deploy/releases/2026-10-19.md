# Release 2026-10-19 — unit codes follow eFinance, two names, eFinance client sends eFinance's code

Date: 19/10/2026
Operator: Marios on the server (`ecapital-release-on-server --ref claude/ecstatic-cray-g0zhkx`)
Migrations: 0024 `unit_codes_follow_efinance`, applied by the release script. Seed: not needed.

## What this release brings

Owner decision of 19/10/2026 (ADR-0034), prompted by eFinance's note of the
same day.

- **Six unit codes move to eFinance's**: `PAF`→`PAP`, `KYP`→`TRD`, `NAM`→`ARC`,
  `POL`→`CHR`, `MHS`→`MH`, `PHC`→`HC`. `code`, `entity_code` and
  `efinance_code` are one string on every unit.
- **Two names move to eFinance's spelling**: «Νοσοκομείο Αρχιεπίσκοπος
  Μακάριος ΙΙΙ» and «Κέντρα Υγείας» (the directorate ΠΦΥ keeps its name).
- **The eFinance client sends `efinance_code`** on the contract push and
  the budget-position reads, and the entity sync matches eFinance's `code`
  first. This closes the hazard eFinance found: a push for one of the six
  units would have been refused the day its table became identity.
- **Nothing is renumbered.** Existing project codes, asset tags and work
  order references keep the prefix they were issued under; the next one a
  renamed unit opens takes the new prefix.
- eArchive site codes move with the unit codes. **The eArchive token stays
  out until eArchive files under the new codes** (runbook §11.2).
