# Release 2026-11-05 — framing refused on every answer (clickjacking finding)

Date: 05/11/2026
Operator: Marios on the server (`ecapital-release-on-server --ref claude/ecstatic-cray-g0zhkx`)
Migrations: none. Seed: none.

## What this release brings

The penetration test of the estate (05/11/2026) reported clickjacking on
eMAP and the dose application: a page loaded inside an attacker's frame
still carries the viewer's session, so a click on a decoy lands on the real
page. eCapital was not named, but it had the same gap. Now:

- **Every answer from the web app and the API carries**
  `Content-Security-Policy: frame-ancestors 'none'` and
  `X-Frame-Options: DENY`, plus `X-Content-Type-Options: nosniff` and a
  `Referrer-Policy`. Set in the applications themselves (`next.config.ts`,
  `security-headers.middleware.ts`), not in nginx, so they travel with the
  release and need no server edit.
- A filed HTML file keeps its sandbox and now carries the framing rule
  inside it as well.
- eCapital frames nothing of its own, so `'none'` breaks nothing.

app, each pair reading `DENY` and `frame-ancestors 'none'`.
