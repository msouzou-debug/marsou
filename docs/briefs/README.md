## Errata agreed with the owner

- **Unit count.** CAPEX-01 §1 and §4 say "nine hospitals plus three services". The Capex Plan has eleven units: eight hospitals plus three services. Troodos and Kyperounta are the same hospital, so the ninth was a double count (18/09/2026). Code and seeds used eleven units from that reconciliation. **Update, 19/09/2026:** the owner added `HQ` (Κεντρικά Γραφεία) as a twelfth unit, type `CENTRAL`, directorate `KENTRIKI_DIOIKISI` — Central Administration can commission capital works of its own, and CAPEX-01 §4's count never covered it because the Capex Plan sheet has no HQ rows to count (ADR-0019 §5). **Later the same day** the owner took the Ambulance Service out of ΟΚΥπΥ, so the count is eleven again: eight hospitals, two services (ΔΥΨΥ, ΠΦΥ) and HQ. The Troodos unit still carries both spellings as aliases, and HQ carries none. See the bullet below and ADR-0024.
- **Project phases.** CAPEX-01 §4 lists eight phases, CAPEX-03 §4 says the target has nine. The code inserts `PREPARATION` between `IDEA` and `APPROVED` to hold the 70 preparation rows. Not yet confirmed by the owner; change `packages/shared/src/project.ts` if the ninth phase is something else.
- **Budget changes after approval.** Finance only (19/09/2026). See ADR-0014.
- **Euro format:** eFinance uses `1.234,56 €`; UI brief §1 says `€ 84.000`. Owner decision 19/09/2026: match eFinance, `1.234,56 €` everywhere.
- **eMetroon is now eArchive.** CAPEX-01 §1 and §3 say «eMetroon»; the document system was renamed eArchive on the server (paths still say `emetroon`). The brief text is kept as written.
- **eCapital files documents with eArchive; it does not store them.** CAPEX-01 §4 lists a `document` table and §5 puts drawings, contracts and certificates in M8. Owner decision and eArchive brief, 19/09/2026: eCapital sends the paper to eArchive, keeps the protocol number eArchive assigns, and holds no archive of its own — the bytes under `DOCUMENT_STORE_DIR` are the operational copy a multipart upload needs in hand and nothing more. Migration `0014_earchive_outbox.sql` builds `document`, `dms_outbox` and `dms_event`; the queue row is written in the **same transaction** as the document row, so a filed document and a queued item cannot come apart. Three item types are sent today — the award decision, the business case and an approved variation — and permits follow with M5, payment certificates later. A corrected document is a **new item** with a new `source_ref` and a `SUPERSEDES` relation, never an edit of something already protocolled. eArchive calls back on `POST /api/v1/dms/events` for deletes and legal holds: a delete leaves a tombstone, because there is no file copy here to delete. **Until the token is on the server the queue holds** — documents are recorded and queued and nothing is sent, which is a state the deployment is meant to be able to sit in. See ADR-0023, INTEGRATION-eFinance-eMAP-eCapital.md §6 and `docs/integration/ecapital-dms-samples/`.
- **One CAPEX budget code per contract.** Owner decision 19/09/2026; eFinance's draft contract assumes it. **Done, 19/09/2026 (ADR-0025):** `contract.budget_code` and a reference table of eFinance's CAPEX codes (five real, fifteen placeholders until eFinance publishes the rest), `GET /budget-codes?kind=capex`, `POST /budget-codes/sync`, and the S07a/S07/S07e screens.
- **The Ambulance Service is out of ΟΚΥπΥ** (owner decision, 19/09/2026). Υπηρεσία Ασθενοφόρων is not a unit of this register any more. The `ambulance` org unit (`AMB`) and everything under it — its projects, contracts, budget lines, cost rows, users and areas — are removed by migration `0012_unit_codes_earchive.sql` and are gone from the seed, so the register is **eleven units**: eight hospitals, two services and HQ. CAPEX-03 §3's eleventh row count (ΥΠΗΡΕΣΙΑ ΑΣΘΕΝΟΦΟΡΩΝ, 4 rows) and its directorate of the same name are therefore source facts about the February spreadsheet, not facts about the register. **CAPEX-03 §5 gains a fifteenth validation rule, V15 «η μονάδα ανήκει στον ΟΚΥπΥ»** (ERROR, blocking, added to §9's list of rules that turn a `--commit` back into a dry run): a row whose unit is one the profile lists under `units_out_of_scope` is reported and not imported. It is not V04 — V04 tells the reader to add the spelling as an alias, which here would put the service back in the register — and the February file fails it on four rows. See ADR-0024.
- **Unit codes follow eArchive** (owner decision, 19/09/2026). All three systems key a place by eArchive's site abbreviation, so `org_unit.code` and `org_unit.entity_code` are now the same string on every unit and ADR-0019 §1's table is superseded: LMS→`LGH`, TRD→`KYP`, NAM3→`NAM`, PCH→`POL`, DYP→`MHS`, PFY→`PHC`; NGH, LAR, PAF, FAM and HQ unchanged. Names do not change — Τροόδους keeps its Greek and English names and takes `KYP` — and neither do the unit ids. The seeded project codes move with the prefix (ADR-0014): `PCH-2026-001` is `POL-2026-001`, the same project. Contract references (`CAP-YYYY-NNNN`) carry no unit code and do not change. The eFinance codes this replaces (PAP, LGH, ARC, CHR, MH, HC, TRD) are kept as a lookup in ADR-0024 «until eFinance aligns», not in any column. See ADR-0024, which supersedes ADR-0019's code list; the rest of ADR-0019 stands.
- **CNS entity code.** eFinance's `CNS` is Central Nursing Services (Greek name to be confirmed by the owner). It has no eCapital unit; capital work for it files under HQ (owner decision 19/09/2026).
- **FBL5N against FBL1N.** CAPEX-01 §7 and CAPEX-03 §7 name «FBL5N» as the actuals extract beside KSB1. `packages/shared/src/cost.ts` — the contract the API and the web app share — says `FBL1N`. FBL5N is the customer line-item report and FBL1N the vendor one, and what a clerk runs to get invoices by supplier is FBL1N. **The contract wins:** the enum, the import profile (`apps/api/src/cost/profiles/fbl1n.yaml`) and the routes all say FBL1N. If ΟΚΥπΥ's finance office really does run FBL5N, the fix is a new profile beside the other three and a value on the enum, not a rename.
- **Cost centre on a project.** CAPEX-01 §4 puts `cost_centre` on `org_unit` and on `area` and not on `project`. R14's third matching step — «matches on WBS then PO then cost centre» — has nothing to compare against without it: a KSB1 posting carries a cost centre, and most postings carry neither a WBS nor a purchase order. `project.cost_centre` is added by migration `0011_m2_cost.sql` and filled by the seed. See ADR-0021 §3.
- **The retention base on a payment certificate.** CAPEX-01 §7's shorthand reads as retention on the work done; `packages/shared/src/cost.ts` says `retentionHeld = retentionPct × (workDone + materials)`. The shared contract is what the web app is built against, so that is what the API computes. ADR-0021 §10.
- **Glossary terms for M2.** CAPEX-02 §7 fixes «Πιστοποίηση πληρωμής» for a payment certificate and «Κρατήσεις» for retention. The first M2 build used «Πιστοποιητικό πληρωμής» and «Παρακράτηση» because the project manager's instructions named those words, not because of an owner decision; the strings now follow §7 (done 19/09/2026). «Δεδουλευμένα» is used for the year-end accruals, which §7 has no entry for.
- **`budget_line.category` is a cost category, not a kind of project.** Migration 0005 typed it as `project_category`; nothing ever wrote it. Migration 0011 retypes it as text with a closed list — `works`, `equipment`, `fees`, `contingency`, `other` — in the lower-case spelling the interface resolves as an i18n key suffix, with `uncategorised` («Χωρίς κατηγορία») for money that has none. ADR-0021 §7.
