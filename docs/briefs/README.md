## Errata agreed with the owner

- **Owner steer, 20/09/2026: start simple, expand later.** The system goes live as a plain capital-and-maintenance register first. M4 (assets) and later milestones are scoped lean on purpose: the fields the brief lists, no whole-life depreciation model, no spares, no meter analytics. Anything beyond that is built when a hospital asks for it.
- **Screen tiers, 20/09/2026.** The same capital-and-maintenance-first steer, applied to training: every screen is either **day one** (trained and used from the pilot's first day) or **optional** (built and reachable in the app, held back to phase two). The decision lives as data, not prose — `tier: "day-one" | "optional"` on every `apps/web/src/help/map.json` entry, enforced by `scripts/check-help-mapping.mjs`'s `findInvalidTiers` (CI fails on a missing or unknown tier). It renders as a chip (TierChip, «Ημέρα 1» / «Προαιρετικό») next to a screen's title in the S25 help drawer and grouped in the S26 help centre's screen list; the per-persona PDF guides (ADR-0027) order each persona's chapters day-one first, then a divider page, then the optional chapters, and the cover lists the day-one screens. `docs/manual/README.md`, generated by `scripts/manual-index.mjs` (run as part of `pnpm guides:build`), is the plain-table index of every screen's tier, title in both languages and personas. The five M4 (assets) screens — register, detail, form, label sheet, scan route — and the asset replacement forecast are not yet routes in `help/map.json` (M4 lands separately, on the main checkout); their tier decision (all day-one except the replacement forecast, which is optional) is recorded by hand in `docs/manual/README.md` until they do.
- **M3 decisions, 20/09/2026.** Infection Control validates the seeded ICRA matrix before the pilot (1); the strict-reading assumptions in ADR-0026 stand (2); Cyprus public holidays are left out of the approval clock (3); approver appointments per hospital are an admin set-up step before go-live (4).
- **Unit count.** CAPEX-01 §1 and §4 say "nine hospitals plus three services". The Capex Plan has eleven units: eight hospitals plus three services. Troodos and Kyperounta are the same hospital, so the ninth was a double count (18/09/2026). Code and seeds used eleven units from that reconciliation. **Update, 19/09/2026:** the owner added `HQ` (Κεντρικά Γραφεία) as a twelfth unit, type `CENTRAL`, directorate `KENTRIKI_DIOIKISI` — Central Administration can commission capital works of its own, and CAPEX-01 §4's count never covered it because the Capex Plan sheet has no HQ rows to count (ADR-0019 §5). **Later the same day** the owner took the Ambulance Service out of ΟΚΥπΥ, so the count is eleven again: eight hospitals, two services (ΔΥΨΥ, ΠΦΥ) and HQ. The Troodos unit still carries both spellings as aliases, and HQ carries none. See the bullet below and ADR-0024.
- **Project phases.** CAPEX-01 §4 lists eight phases, CAPEX-03 §4 says the target has nine. The code inserts `PREPARATION` between `IDEA` and `APPROVED` to hold the 70 preparation rows. Not yet confirmed by the owner; change `packages/shared/src/project.ts` if the ninth phase is something else.
- **Budget changes after approval.** Finance only (19/09/2026). See ADR-0014.
- **Euro format:** eFinance uses `1.234,56 €`; UI brief §1 says `€ 84.000`. Owner decision 19/09/2026: match eFinance, `1.234,56 €` everywhere.
- **eMetroon is now eArchive.** CAPEX-01 §1 and §3 say «eMetroon»; the document system was renamed eArchive on the server (paths still say `emetroon`). The brief text is kept as written.
- **eCapital files documents with eArchive; it does not store them.** CAPEX-01 §4 lists a `document` table and §5 puts drawings, contracts and certificates in M8. Owner decision and eArchive brief, 19/09/2026: eCapital sends the paper to eArchive, keeps the protocol number eArchive assigns, and holds no archive of its own — the bytes under `DOCUMENT_STORE_DIR` are the operational copy a multipart upload needs in hand and nothing more. Migration `0014_earchive_outbox.sql` builds `document`, `dms_outbox` and `dms_event`; the queue row is written in the **same transaction** as the document row, so a filed document and a queued item cannot come apart. Three item types are sent today — the award decision, the business case and an approved variation — and permits follow with M5, payment certificates later. A corrected document is a **new item** with a new `source_ref` and a `SUPERSEDES` relation, never an edit of something already protocolled. eArchive calls back on `POST /api/v1/dms/events` for deletes and legal holds: a delete leaves a tombstone, because there is no file copy here to delete. **Until the token is on the server the queue holds** — documents are recorded and queued and nothing is sent, which is a state the deployment is meant to be able to sit in. See ADR-0023, INTEGRATION-eFinance-eMAP-eCapital.md §6 and `docs/integration/ecapital-dms-samples/`.
- **One CAPEX budget code per contract.** Owner decision 19/09/2026; eFinance's draft contract assumes it. **Done, 19/09/2026 (ADR-0025):** `contract.budget_code` and a reference table of eFinance's CAPEX codes (five real, fifteen placeholders until eFinance publishes the rest), `GET /budget-codes?kind=capex`, `POST /budget-codes/sync`, and the S07a/S07/S07e screens.
- **The Ambulance Service is out of ΟΚΥπΥ** (owner decision, 19/09/2026). Υπηρεσία Ασθενοφόρων is not a unit of this register any more. The `ambulance` org unit (`AMB`) and everything under it — its projects, contracts, budget lines, cost rows, users and areas — are removed by migration `0012_unit_codes_earchive.sql` and are gone from the seed, so the register is **eleven units**: eight hospitals, two services and HQ. CAPEX-03 §3's eleventh row count (ΥΠΗΡΕΣΙΑ ΑΣΘΕΝΟΦΟΡΩΝ, 4 rows) and its directorate of the same name are therefore source facts about the February spreadsheet, not facts about the register. **CAPEX-03 §5 gains a fifteenth validation rule, V15 «η μονάδα ανήκει στον ΟΚΥπΥ»** (ERROR, blocking, added to §9's list of rules that turn a `--commit` back into a dry run): a row whose unit is one the profile lists under `units_out_of_scope` is reported and not imported. It is not V04 — V04 tells the reader to add the spelling as an alias, which here would put the service back in the register — and the February file fails it on four rows. See ADR-0024.
- **Unit codes follow eArchive** (owner decision, 19/09/2026). All three systems key a place by eArchive's site abbreviation, so `org_unit.code` and `org_unit.entity_code` are now the same string on every unit and ADR-0019 §1's table is superseded: LMS→`LGH`, TRD→`KYP`, NAM3→`NAM`, PCH→`POL`, DYP→`MHS`, PFY→`PHC`; NGH, LAR, PAF, FAM and HQ unchanged. Names do not change — Τροόδους keeps its Greek and English names and takes `KYP` — and neither do the unit ids. The seeded project codes move with the prefix (ADR-0014): `PCH-2026-001` is `POL-2026-001`, the same project. Contract references (`CAP-YYYY-NNNN`) carry no unit code and do not change. The eFinance codes this replaces (PAP, LGH, ARC, CHR, MH, HC, TRD) are kept as a lookup in ADR-0024 «until eFinance aligns», not in any column. See ADR-0024, which supersedes ADR-0019's code list; the rest of ADR-0019 stands.
- **CNS entity code — corrected, 20/09/2026.** Yesterday's bullet here read "Central Nursing Services, no unit, files under HQ (owner decision 19/09/2026)". **That was wrong, on both counts.** CNS is «Κοινοτική Νοσηλευτική» (Community Nursing), and it gets its own eCapital unit — `community-nursing`, code and entity code `CNS`, type SERVICE, directorate PFY (ASSUMPTION: Primary Healthcare is the closest fit among the six directorates; flagged for the owner to confirm) — filing under its own eArchive folder rather than HQ's. See ADR-0024's addendum, migration `0018_cns_unit_and_efinance_codes.sql`, `docs/INTEGRATION-eFinance-eMAP-eCapital.md` §2 and §6.
- **FBL5N against FBL1N.** CAPEX-01 §7 and CAPEX-03 §7 name «FBL5N» as the actuals extract beside KSB1. `packages/shared/src/cost.ts` — the contract the API and the web app share — says `FBL1N`. FBL5N is the customer line-item report and FBL1N the vendor one, and what a clerk runs to get invoices by supplier is FBL1N. **The contract wins:** the enum, the import profile (`apps/api/src/cost/profiles/fbl1n.yaml`) and the routes all say FBL1N. If ΟΚΥπΥ's finance office really does run FBL5N, the fix is a new profile beside the other three and a value on the enum, not a rename.
- **Cost centre on a project.** CAPEX-01 §4 puts `cost_centre` on `org_unit` and on `area` and not on `project`. R14's third matching step — «matches on WBS then PO then cost centre» — has nothing to compare against without it: a KSB1 posting carries a cost centre, and most postings carry neither a WBS nor a purchase order. `project.cost_centre` is added by migration `0011_m2_cost.sql` and filled by the seed. See ADR-0021 §3.
- **The retention base on a payment certificate.** CAPEX-01 §7's shorthand reads as retention on the work done; `packages/shared/src/cost.ts` says `retentionHeld = retentionPct × (workDone + materials)`. The shared contract is what the web app is built against, so that is what the API computes. ADR-0021 §10.
- **Glossary terms for M2.** CAPEX-02 §7 fixes «Πιστοποίηση πληρωμής» for a payment certificate and «Κρατήσεις» for retention. The first M2 build used «Πιστοποιητικό πληρωμής» and «Παρακράτηση» because the project manager's instructions named those words, not because of an owner decision; the strings now follow §7 (done 19/09/2026). «Δεδουλευμένα» is used for the year-end accruals, which §7 has no entry for.
- **`budget_line.category` is a cost category, not a kind of project.** Migration 0005 typed it as `project_category`; nothing ever wrote it. Migration 0011 retypes it as text with a closed list — `works`, `equipment`, `fees`, `contingency`, `other` — in the lower-case spelling the interface resolves as an i18n key suffix, with `uncategorised` («Χωρίς κατηγορία») for money that has none. ADR-0021 §7.
- **M3 — shutdown permits and ICRA (19/09/2026, ADR-0026).** Nine things CAPEX-01 §6 leaves open, each resolved the stricter way and each one the owner's to confirm.
  - **`PTW-<UNITCODE>-<YYYY>-<NNN>`** is the permit reference. No brief names a prefix; «permit to work» is what the paper form is called. Allocated on submission, immutable after it, same counter machinery as the project code (ADR-0014).
  - **`WARD_MANAGER` is an approval role.** §6.4 asks for «ward/department manager for every clinical area touched»; CAPEX-01 §4's `permit_approval.role` has no such value, so `packages/shared/src/permit.ts` adds one.
  - **SAFETY signs when ILSM is required.** §6.4 never names Safety and §6.3 makes ILSM mandatory with «notification to the fire officer» in it. A notification with no signature behind it cannot be shown to have happened.
  - **The Hospital Director's threshold is 72 hours**, as `PERMIT_DIRECTOR_THRESHOLD_HOURS`. §6.4 says «above a threshold duration» and stops. Lowering it only ever adds an approver.
  - **An approval line is due in two working days**, the RFI's clock (ADR-0017) with weekends skipped. Cyprus public holidays are not modelled — that calendar is data nobody has given us.
  - **`system_feed` carries indirect impact until M4.** §6.1 points at `asset.serves_area_ids`, which arrives with the asset register. The seam is `GET /areas/impact`; nothing above it changes when M4 lands.
  - **`REDUNDANT_HALVES` is «two permits on the same system in the same unit at once»** until the assets model A and B feeds. It warns more often than it eventually will, which is the right way round for medical gas.
  - **The seeded ICRA matrix `OKYPY-ICRA-2.0-2026.1` is the ASHE standard, not yet the ΟΚΥπΥ edition.** It carries «Προς επικύρωση από την Επιτροπή Ελέγχου Λοιμώξεων» in `notesEl` and is changed by publishing a new version through `POST /icra/matrix/versions`, never by editing the seed. §2's two hard cells are in it: Type C in a high-risk area is Class IV, and Class II is refused for construction or renovation.
  - **Only the clinical acceptor may close a permit**, and the signature is stamped from the caller rather than read from the body. The consequence is deliberate and visible: a permit touching no area with a clinical owner, in a unit with no Nursing or Infection Control appointment, cannot be closed until somebody is appointed.
  - **Approver scoping is per user**, in `area_clinical_owner` and `unit_approver`, following ADR-0020 rather than CAPEX-01 §4's `area.clinical_owner_group_id` — an Entra group in a system that stopped using them.
- **M3 self-approval on the route, 19/09/2026 (ADR-0026).** A permit-detail screenshot showed the requester (Larnaca's sole TECHNICAL appointment) resolved as her own approver, decide buttons included. `resolveApprover` now applies ADR-0015's segregation rule to routing — another holder of the same role in the unit is preferred over the requester, and the line is left unassigned rather than self-assigned when there is none — and `decide()` refuses 409 `errors.permitSelfApproval` when the caller is the permit's own requester, an administrator included.
- **M3 contract reconciliation, 19/09/2026 (ADR-0026 §11).** The web and API halves of M3 were built in parallel and met at the merge. `packages/shared/src/permit.ts` gained `projectId` on `PermitListRow` and the `ApproverScopes` schemas, and lost two constraints that were attached to the wrong moment: `ShutdownPermitDraft` now takes a **partial** create (S11 autosaves the request when the requester leaves step 1, before any area or date exists) and `ShutdownPermit.affectedAreas` no longer carries `.min(1)`. Neither rule is gone — both are enforced at the SUBMITTED transition, where a half-finished draft is refused with `errors.permitNoAreas` or `errors.permitWindowRequired`. Migration `0016_permit_partial_draft.sql` adds `shutdown_permit.window_provisional` so the planned window can stay two non-null timestamps the screen formats while still being known to be a placeholder. Clash keys are `permitClash.<KIND>` in both catalogues; `GET/PUT /admin/users/:id/approver-scopes` and `GET /permits/:id/audit` are new.
- **M4 — the asset register, 20/09/2026 (ADR-0028).** Built lean on the owner steer above, and the seam ADR-0026 left open is now closed.
  - **`<UNITCODE>-<CLASS>-<NNNN>`** is the asset tag — `NGH-MGS-0001` — allocated per unit and class by `ecapital.allocate_asset_tag` with ADR-0014's counter and advisory lock, and immutable afterwards. The class codes are `BLD HVA ELE MGS WAT FIR LFT BIO ITE OTH`; they are three letters because the label is small and a technician reads it out loud, and they cannot change later without relabelling the estate. The unit and the class cannot move either, because both are inside the tag: an asset that really moved hospital is a disposal here and a new asset there.
  - **`asset.serves_area_ids` now answers `GET /areas/impact`, per system.** Where a unit has an asset carrying a system and recording what it serves, that asset answers and `system_feed` is not consulted for that system; every other system still comes off the feed. Per system and not per unit, because a half-surveyed hospital has the medical gas in the register and the HVAC risers not. An asset fires on the system alone, wherever it stands, which for a plant-room asset warns more often than its feed did — the right way round for medical gas. Nothing above the route changed, which is what ADR-0026 promised.
  - **A technician may record a condition and a reading, and nothing else.** A row policy cannot be narrowed to one column, so the condition goes through `ecapital.record_asset_condition`, SECURITY DEFINER, which carries the rule and moves the band and its date only. `noteEl` on that request is accepted and **not stored**: the lean register has no note column, and the sentence belongs on M5's work order.
  - **An asset's papers are filed with eArchive through the existing outbox** (ADR-0023): `source_module: asset_document`, `source_ref: asset_doc:<asset_id>:<n>`, «Συμβάσεις» for the commissioning pack, the certificate and the warranty and «Διοίκηση» for the manual, the drawing and the photograph, folder hint the unit's code. `document_kind` gains `ASSET_DOCUMENT`.
  - **The history is assembled on read, never stored**, from the asset's audit rows, its readings, its papers, its source project and contract, and the permits touching it. WORK_ORDER and DEFECT are on the contract's list of kinds and wait for M5; the route returns what exists.
  - **Left out on the steer, and each one a new ADR if it is ever wanted:** no depreciation model, no spares or stores, no meter analytics beyond the plain reading row. `wholeLife.maintenanceToDate` is null and not zero until M5 has work orders to add up.
  - **`defect.asset_id`** becomes `uuid` with a foreign key, which is what CAPEX-01 §4 always meant; migration 0006 left it as unreferenced text «until the table exists». `AssetDetail.openDefects` counts the open handover defects on the asset.
- **Community Nursing is a unit, and the register is twelve again, 20/09/2026 (ADR-0024's addendum).** Corrects the CNS bullet above. `org_unit` gains `community-nursing` (code and entity code `CNS`, type SERVICE, directorate PFY — ASSUMPTION, flagged for the owner — no cost centre, no projects yet, Capex import alias «ΚΟΙΝΟΤΙΚΗ ΝΟΣΗΛΕΥΤΙΚΗ»), inserted idempotently by migration `0018_cns_unit_and_efinance_codes.sql` and carried by the seed. Eight hospitals, two services, HQ and Community Nursing: twelve. Every place that counted "eleven units" for the admin's own unit list moves to twelve with it — `apps/web/e2e/m0.spec.ts`, the web mocks, the API tests.
- **eFinance keeps its own entity keys permanently — the two-code model, 20/09/2026 (ADR-0022's addendum, ADR-0024's addendum).** ADR-0024 §2 kept the six eFinance codes eCapital's `entity_code` moved away from (`PAP`, `LGH`(unchanged), `TRD`, `ARC`, `CHR`, `MH`, `HC`) as a lookup document "until eFinance aligns". eFinance has since said it will not: those strings are foreign keys across twelve of its own tables and in SAP. So the lookup becomes a permanent column instead: `org_unit.efinance_code` (nullable, unique), added by the same migration as CNS, mapped NGH→NGH, LAR→LAR, PAF→PAP, LGH→LGH, KYP→TRD, NAM→ARC, POL→CHR, FAM→FAM, MHS→MH, PHC→HC, HQ→HQ, CNS→CNS. `entity_code` keeps meaning what ADR-0024 made it mean — eArchive's abbreviation, our own key — and does not move again; `efinanceCode` is exposed alongside it on the shared `OrgUnit` schema and `GET /org-units`, and `OrgUnitsService.efinanceCodeFor(orgUnitId)` is the one place that translates, for the future SAP actuals / spent-ledger reader (`docs/INTEGRATION-eFinance-eMAP-eCapital.md` §5). `EFinanceBudgetCodeReader` is unchanged — there is no entity on a budget-code row.
